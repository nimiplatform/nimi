## Hard Boundaries
- Repo-wide normative authority lives under `.nimi/spec/**`; retired pre-cutover authority history now lives in Git and must not regain active truth. Admitted app slices may live under `apps/**/spec/**` if they do not create parallel truth. Nimicoding package authority lives in the external `@nimiplatform/nimi-coding` package; this host consumes its retained methodology and deterministic tooling through the guarded package scripts and admitted `.nimi/{config,contracts,methodology}/**` host projections. Host-local truth lives under `.nimi/**`; `.local/**` is legacy local execution/evidence compatibility space; tracked support inputs live under `config/**`; `dev/**` is inactive.
- High-risk authority-bearing work needs preflight before implementation with `Spec Status`, `Authority Owner`, `Work Type`, and `Parallel Truth`.
- `Work Type=alignment` must align to existing authority with no parallel truth. `Work Type=redesign` changes authority/canonical ownership and must not proceed without prior `/.nimi/spec/**` alignment.
- Debug/fix order: `runtime` → `sdks/typescript` → `apps/desktop`/`apps/web`. Reuse `@nimiplatform/kit` first for UI work via `kit/README.md` and `.nimi/spec/platform/kernel/tables/nimi-kit-registry.yaml`.
- UI/UX work: read `DESIGN.md` and `kit/DESIGN.md` before changing shared Nimi UI surfaces. Treat them as generated AI/tool-facing projections from `.nimi/spec/platform/kernel/**`, not canonical authority. If the projection is missing, stale, or conflicts with `.nimi/spec/**`, update the relevant `nimi-ui-*.yaml` spec tables first and regenerate with `pnpm generate:nimi-design-artifacts`; do not hand-edit generated design artifacts.
- Design artifacts: `kit/design_tokens.json`, `kit/design-projection.json`, and `kit/tailwind-theme.css` are generated interoperability/projection outputs for tooling and audits. They follow Nimi's Tailwind v4 CSS-first stack and must not become runtime truth; runtime Kit CSS still comes from the existing spec-derived UI generation path.
- Fail closed on contract violations. No legacy shims, no pseudo-success, no app-level REST bypass, no provider/model hardcoding.
- Boundary enforcement: Desktop/Web must not import `runtime/internal/**`; SDK must not cross `realm`/`runtime` private boundaries; Runtime must not import `sdks/**` or `apps/**`; no file collisions or forwarding shells outside `index.ts`.
- Workflow ownership: the external AI host exclusively owns task lifecycle, planning, decomposition, subagents, waiting, resumption, and completion state. Nimi-coding must not create, mirror, advance, resume, close, or execute host workflow state. Use only the guarded package scripts declared in `package.json`; direct package bootstrap, projection mutation, and package workflow commands are forbidden.
- Nimi2D Image2: use the standard `@nimiplatform/nimi2d` provider command surface for live image resource generation: `image2-provider-plan`, `image2-provider-run`, `image2-register-output`, `image2-compare-pixels`, `image2-postprocess`, `image2-layer-workflow`, `image2-distribution-report`, and `image2-demo-suite`. On Windows, if PowerShell blocks the `codex.ps1` shim, use `image2-provider-run --codex-bin codex.cmd`. Never use ad hoc session prompts as provider evidence, and never treat provider artifacts as formal admission before atlas, layer-input, Generation Bench, and runtime proof gates pass.
