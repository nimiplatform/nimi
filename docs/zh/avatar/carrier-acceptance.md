# Carrier 视觉呈现验收（Carrier Visual Acceptance）

**Carrier** 是承载与渲染具身化（Embodiment）的宿主表面（例如视口、画布或浮动窗口），也是角色在界面中实际呈现的物理区域。Carrier 视觉呈现验收契约用于决定特定具身化资源包是否可以在指定的 Carrier 表面上加载与显示。

## 验收决策机制

| 匹配情况 | 判定与执行结果 |
| --- | --- |
| 具身化完全匹配 Carrier 的能力与规格 | 接受：完成初始化并启动渲染 |
| 具身化超出 Carrier 限制（如动作复杂度档位或规格） | 降级或拒绝：退回到受控的简化呈现（如 2D 静态图或精简动作档位） |
| 具身化定义或资源结构损坏 | 拒绝：返回结构化的配置/契约校验错误 |
| 具身化违反 Carrier 安全或平台策略 | 拒绝：返回带具体原因的策略拦截错误 |

Carrier 不支持不可预测的模糊渲染或残缺渲染。所有的接收校验都在装载前通过强类型契约严格完成，确保结果在接受、降级或拒绝之间具有完全的确定性。

## 为什么需要 Carrier 级准入判断

如果具身化资源可以在任意表面无限制挂载，专为高性能桌面端设计的重度 3D 资产可能会导致低功耗移动设备内存溢出或掉帧；为特定渲染后端（如 Live2D）制作的资源也可能被错误挂载到不兼容的 3D 引擎（如 three-vrm）上。

Carrier 视觉呈现验收契约由宿主明确声明自身的渲染能力边界。资源包声明所需条件，Carrier 声明支持特性，平台在启动渲染管线前进行前置校验与裁定。

## 典型开发者场景

### 1. 受限设备加载重度具身化资源

用户在低功耗设备上尝试加载包含复杂骨骼动画与高精度贴图的角色包：

1. **Carrier 声明能力边界**：声明所支持的后端类型、最大动画复杂度档位以及纹理/资源内存上限。
2. **读取资源包清单**：解析具身化包声明的技术要求与配置。
3. **能力对比与评估**：通过验收契约比对资源包需求与宿主能力。
4. **触发优雅降级**：检测到完整具身化超出设备性能档位，契约决定退回到经过验证的简化呈现层（如精简动作或 2D 立绘）。
5. **明确状态通知**：向宿主返回结构化原因说明（例如 `"当前设备性能配置未达到完整动作档位的最低要求"`）。

降级过程可预期且具有确定性，避免界面白屏、卡死或未捕获的渲染异常。

### 2. 渲染后端不匹配拦截

具身化资源要求 Live2D 运行时，但当前宿主 Carrier 仅提供 VRM 3D 支持：

1. **后端类型比对**：Carrier 检查资源包声明的 `backendKind`。
2. **检测不兼容**：识别到后端不匹配（请求 `live2d`，宿主仅支持 `vrm`）。
3. **返回类型化错误**：直接返回不支持的渲染后端错误代码。
4. **阻断错误渲染**：Carrier 提前中止管线，不进行无效的 WebGL 上下文初始化。

通过判别联合（Discriminated Union）在初始化前完成匹配检查，彻底消除跨引擎渲染错误。

### 3. 会话中动态热更新

创作者在用户与角色交互期间推送了具身化资源包的更新版本：

1. **接收更新通知**：通过更新通道捕获到新版具身化描述符。
2. **二次评估**：Carrier 针对当前宿主契约对新版本重新进行验收比对。
3. **平滑过渡**：如果兼容，Carrier 在平滑过渡时限内完成新老资产热替换。
4. **不兼容阻断**：若新版本超出设备规格，Carrier 维持当前运行版本或平稳转入 `degraded:embodiment-incompatible` 提示状态。
5. **保障会话连续**：创作者的版本迭代不会突兀中断用户的正常使用与对话上下文。

## 职责边界与非目标

| 关注维度 | 归属职责 |
| --- | --- |
| 角色核心身份 | 由 Realm 管理；Carrier 仅负责视觉外观呈现 |
| 执行与交互状态 | 由 Runtime 与 LocalAgent 驱动；Carrier 负责视口渲染 |
| 资源包打包与修改 | 具身化包属于创作者发布的不可变制品，Carrier 仅作为只读消费者 |
| 超限渲染 | Carrier 严格遵守声明的能力边界，不进行越界渲染 |
