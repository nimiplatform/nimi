# 六大核心基础协议（Six Core Primitives）

Nimi 平台定义了六项跨世界通用的核心基础协议（归属于 `P-PROTO-*` 规则族），作为数字世界互联互通的技术基石。各虚拟世界可自主定义其内部机制与剧情规则；凡涉及跨越世界边界的交互与状态流转，均遵循这六项基础契约。

## 六大基础协议对照

| 基础协议 | 规则编号 | 核心职责 | 架构定位 |
| --- | --- | --- | --- |
| **Timeflow（时间流）** | `P-PROTO-100` | 协调世界内部的时钟推进、时间快慢与时序同步 | 维护多用户与智能体交互的时序一致性 |
| **Social（社交网络）** | `P-PROTO-101` | 维护跨世界的全局好友图谱、关系层级与群组 | 沉淀统一社交关系，避免在不同世界重复建立联系 |
| **Economy（经济系统）** | `P-PROTO-102` | 统一管理资产流转、清算分配与跨界价值交换 | 维护可审计、防双花的仅追加财务流水账本 |
| **Transit（跨界漫游）** | `P-PROTO-103` | 负责参与者在世界之间移动的路由与会话连续性 | 依托 OASIS 枢纽保障身份连续性与平稳容错 |
| **Context（情境语义）** | `P-PROTO-104` | 规范世界背景、世界观设定（Lore）及环境交互语义 | 保证异构应用理解统一的世界情境含义 |
| **Presence（在场状态）** | `P-PROTO-105` | 跟踪用户与智能体在特定场景中的在场与活跃度 | 支持多人空间同步、场景准入与状态感知 |

## 权威分工与架构层级

| 架构层级 | 权责定位 |
| --- | --- |
| **平台核心协议（Platform Protocol）** | 制定 Schema 数据结构、版本演进准则与合规性校验标准 |
| **服务端 Realm** | 统一作为六大基础协议的权威数据源与语义仲裁中心 |
| **客户端应用（App）** | 通过 SDK 消费并呈现状态投影，发起符合协议的操作请求 |

## 跨协议的一致性约束

跨界业务通常交叉依赖多项基础协议。为保证全局状态完整，系统推行以下原子性联合约束：
- **漫游复合校验**：一次 Transit 穿越必须同时满足目标世界的 Social（社交准入）、Economy（经济结算）与 Context（情境兼容）；
- **在场以社交为前提**：在受保护的世界中取得 Presence 状态，需先满足该世界的 Social 准入规则；
- **时间与结算窗口对齐**：Timeflow 的世界时钟推进需严格遵守 Economy 的周期性清算窗口。

## 版本演进与契约兼容

- **显式版本声明**：六大协议均具备严格的类型定义，各次交互显式声明 Schema 标识与版本号；
- **Fail-Closed 校验诊断**：载荷若偏离声明的 Schema，系统将执行 fail-closed 并返回结构化错误码与字段级校验明细，便于快速定位缺失或非法字段。
