# 创作者收益与结算管线（Creator Payouts）

在 Nimi 的经济体系中，“收益结算（Payouts）”是指将创作者在数字世界中积累的虚拟商业收益转化为合规真实资金流的完整生命周期管线。底层依赖不可篡改的 `R-ECON-*` 经济账本与经各方确认的分成计划，确保每一笔收益的结算过程可信、公开且具备完整的财务审计凭据。

> 状态说明：已确认为平台演进方向。收益结算所依赖的底层经济模型（`R-ECON-*` 契约、收益分配策略）已明确；提现管线本身与用户提现界面属于已规划的平台方向，当前并非已上线的桌面端功能或公开 App API。

## 收益结算的核心原则

1. **财务流与叙事逻辑彻底解耦**：剧情中角色之间的“虚拟游戏币买卖”属于游戏世界观的故事情节（Story Events），而创作者真实的“商业分成与提现”属于金融级的经济事件（Economic Events），二者在数据结构上严格分离，杜绝混淆。
2. **分成计划强制公开透明**：所有参与分成的团队成员比例均通过正式的分成计划在生效前明确锁定，杜绝任何未向协作者披露的隐性抽成或事后任意改动。
3. **不可篡改的记账保障**：所有收入流水、结算记录与提现行为均以仅追加（Append-Only）方式入账。

## 收益事件生命周期

| 阶段 | 核心动作 | 账本记录形式 |
| --- | --- | --- |
| **1. 收入产生** | 消费者在商城或世界内购买创作者的资产 | 记录 `Purchase` 事件，锁定收入来源及归属作品 |
| **2. 资金累积** | 对应资产的收益在结算周期内安全汇总 | 系统根据生效的分成方案计算各协作者的待结金额 |
| **3. 周期结算** | 触发周期性自动结算或手动结算批次 | 写入 `Settlement` 事件，资金正式转入创作者的可用余额池 |
| **4. 提现结算（规划方向）** | 创作者通过受控提现渠道发起申请 | 写入 `Withdrawal` 事件；具体外部支付网关划拨属于后续平台方向 |

## 账目纠错与争议处理机制

在现实财务运营中，若发生网络交易异常或退款调账，系统遵循严格的追加勘误规范：
- **原始记录完整保留**：原交易事件依旧保存在账本时间线中，不可被物理抹除；
- **追加冲正记录**：系统追加一条显式的 `Correction` 纠错事件，明确引用原交易并附带退款原因说明；
- **财务审计穿透**：财务审计人员能够清晰查阅“该笔交易何时产生，随后在何时因退款发生冲正”，保证企业级内控合规。
