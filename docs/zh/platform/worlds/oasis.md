# OASIS 系统主世界

在 Nimi 的平台核心协议中，OASIS 被定义为全局唯一的**系统主世界**，承担跨世界转场中枢与默认返回枢纽的协议角色。它不属于任何第三方创作者，也无法被任何应用的私有约定取代。

> **当前实现边界说明**：OASIS 作为唯一系统主世界与中转/返回枢纽属于核心协议语义。在当前 Home 的实际交互中，用户浏览世界详情仅读取世界元数据（`WorldCore`），不会调用 `Transit` 原语，也不会触发自动穿梭或切换当前活动世界。

## OASIS 核心定位

| 属性 | 协议规范定义 |
| --- | --- |
| 身份定位 | 全局唯一的系统主世界 |
| 权威归属 | Realm 权威模型中的核心系统实体 |
| 所有权 | 平台公共世界资产，不属于任何第三方创作者 |
| 可替换性 | 不可替换，无法被应用层私有约定覆盖 |
| 协议角色 | 创作者世界之间的唯一权威转场中枢与默认返回目标 |
| Realm 读取端点 | `GET /api/realm/core/oasis`（Realm 提供的标准状态读取路径） |

OASIS 不是商业品牌包装，也不是创作者可以克隆或绕过的临时“新手村”，而是平台多世界拓扑结构在协议层的锚点。

在接口消费层面，`GET /api/realm/core/oasis` 是 Realm 暴露的底层读取端点说明。Desktop、Web 与普通 App 应统一通过 `@nimiplatform/sdk`（受保护 App 由 Runtime 掌管凭据与代理通道）读取相关状态，而不应自行拼接裸 REST 请求绕过平台边界。

## 为什么协议需要定义 OASIS

如果允许任意创作者世界之间直接进行非受控的点对点（P2P）跳转，跨世界平台很快会陷入复杂度高达 $N \times N$ 的互联策略与状态割裂。Nimi 在协议层采用以 OASIS 为中心的星型契约结构：

- **单跳连续性契约（Single-Hop Continuity）**：在协议模型中，创作者世界之间不开放非受控的直连转场，跨世界路径统一经由 OASIS 表达（`World A → OASIS → World B`），从而将 $N \times N$ 的网状协商收敛为每个世界与系统主世界之间的 $N$ 条标准化契约。
- **默认返回枢纽语义**：当参与者离开某个创作者世界或目标世界不可用时，协议将 OASIS 定义为默认返回目标，避免把回退落点绑定在任何单一第三方创作者世界的可用性上。（注：这并不意味着 OASIS 或 Realm 永不宕机；当 Realm 或 OASIS 本身不可达时，客户端遵循故障封闭 Fail-Closed 语义，直接呈现明确的不可用状态。）

## OASIS 与传统“元宇宙中枢”的区别

传统科幻作品常将中心世界描绘为统一渲染和模拟所有物理规则的巨型引擎；而 Nimi 中的 OASIS 是平台协议层面的**语义与社交权威锚点**，而非单一的物理模拟器。

| 属性 | 传统元宇宙式中枢 | Nimi OASIS |
| --- | --- | --- |
| 底层基石 | 集中式物理模拟与统一渲染管线 | 语义模型与由 Realm 治理的权威状态 |
| 规则体系 | 所有子世界强制继承全局物理与引擎规则 | 每个世界自主定义内部玩法、叙事与局部准入规则 |
| 跨世界身份 | 多与特定引擎绑定或松散耦合 | 由 Realm 统一维护，遵循协议级连续性契约 |
| 中枢权威 | 单一应用内部的大厅约定 | 平台核心协议定义的一等系统实体 |
| 可替换性 | 随应用改版或商业策略变更 | 协议内建锚点，不可被第三方创作者世界替换 |

## 协议契约场景说明

以下场景用于说明 OASIS 在 `Transit` 等核心协议契约中的设计语义（如前文所述，当前 Home 浏览世界详情不会触发下述实时转场或自动会话迁移）。

### 契约场景一：在两个创作者世界之间转场

在 `Transit` 协议契约下，当一次从 World A 前往 World B 的跨世界移动发生时：

1. **发起转场契约**：移动请求遵循 `Transit` 原语契约进行结构化表达与校验。
2. **中枢路由语义**：协议路径经由 OASIS 中转（`World A → OASIS → World B`），不开放绕过中枢的创作者世界私自直连。
3. **权威状态一致**：用户的全局账号身份、角色设定与好友关系始终以 Realm 为唯一真相源，外部世界无法在转场中伪造身份或篡改全局关系。
4. **目标世界准入**：World B 在尊重 Realm 全局身份与所有者权限的前提下，依据本世界的场景准入条件与玩法规则接纳参与者。

### 契约场景二：创作者世界不可达时的返回目标

针对第三方创作者世界下线或不可达的情况，协议定义了明确的回退目标语义：

- **无主世界契约的困境**：若缺乏系统级主世界，当某个创作者世界离线时，协议层没有规范的公共落点可供指向。
- **基于 OASIS 的返回契约**：协议将 OASIS 指定为默认返回枢纽，使回退目标不依赖于其他第三方创作者世界。若请求时 Realm 或 OASIS 自身发生通信中断，系统不会伪造本地会话成功，而是按故障封闭（Fail-Closed）原则返回明确的不可用提示。

### 契约场景三：创作者自主权与系统主世界边界

假设某创作者构建了大型核心世界，并希望围绕它组织丰富的系列内容：

- **创作者世界的充分自由**：创作者可以在自己的世界内部自由设计叙事、场景准入条件与特色玩法，创作者世界是平台的一等公民。
- **系统主世界不可替代**：创作者世界不能取代 OASIS 成为系统主世界，也不能私自充当跨世界协议的全局转场仲裁中枢。
- **不越过协议与所有者边界**：任何创作者世界或 App 都不能在协议契约中绕过 OASIS，更不能越过资源所有者（Owner）私自变更 Realm 中的全局状态。
