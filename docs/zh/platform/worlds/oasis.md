# OASIS 系统主世界

OASIS 是每位 Nimi 用户都会经过的核心世界——系统主世界。它内建于平台核心协议中，全局唯一，不属于任何特定创作者，任何 App 也无法用私有逻辑将其取代。

## OASIS 核心定位

| 属性 | 规范定义 |
| --- | --- |
| 身份 | 全局唯一的系统主世界 |
| 权威所有权 | Realm 规范权威模型的核心组成部分 |
| 归属权 | 平台公共资产，不属于任何第三方创作者 |
| 可替换性 | 不可替换，不受 App 私有规则覆盖 |
| 核心角色 | 默认安全回归点；世界间转场的唯一权威中枢 |
| 查询接口 | `GET /api/realm/core/oasis` 提供标准的权威状态查询 |

OASIS 不是一个商业品牌，不是临时搭建的“演示世界”，也不是创作者可以随意克隆或绕过的新手村。它是平台跨世界连续性模型的结构基石。

## OASIS 的设计初衷

多数跨世界平台要么回避中枢设计，要么采取松散的妥协方案：依靠 App 自行约定一个所谓的“主大厅”，各世界之间随意进行点对点 (P2P) 互联。这种方式极易导致用户身份割裂与上下文丢失。Nimi 选择了结构化、可验证的设计路径。

平台的核心机制依赖于 OASIS：

- **单跳连续性协议**：创作者世界之间不开放直接的 P2P 转场通道，所有转场均经由 OASIS 进行路由：World A → OASIS → World B。这保证了用户在切换世界上下文时，身份与状态的连续性是协议级强约束，而非偶然的局部实现。
- **默认安全回归点**：当参与者离开某个创作者世界时，系统会统一导流回 OASIS。这意味着平台始终拥有规范明确的安全停泊点，不会因任何单一创作者世界离线或不可达而导致用户悬挂。

OASIS 是 Nimi 跨世界连续性的骨架——它确保了用户身份、社交关系以及经济凭据在跨越不同创作者世界时，始终具备一致且连贯的意义。

## OASIS 与传统“元宇宙中枢”的区别

传统科幻作品中的 OASIS 通常被设想为统一共享的物理世界引擎。Nimi 借鉴了其“意义中枢”的构想，但在实现上是一个**社会关系与语义权威引擎**，而非庞杂的物理模拟器。

| 属性 | 传统元宇宙式中枢 | Nimi OASIS |
| --- | --- | --- |
| 底层基石 | 物理模拟与渲染管线 | 语义模型与社交关系权威状态 |
| 规则体系 | 所有子世界强制继承全局物理规则 | 每个世界自主定义内部交互与业务规则 |
| 跨世界身份 | 多数为弱绑定或由中心化平台单点持有 | 平台一等公民的权威实体与协议级连续性 |
| 中枢权威 | 属于某一家商业公司的专属服务 | 遵循开放协议的平台级规范模型 |
| 可替换性 | 商业策略决定，时常变更 | 协议内建权威，不可被第三方私有世界取代 |

Nimi OASIS 是跨世界转场的中枢与状态连续性锚点，而不是单一集中的物理游乐场。世界内部的规则由创作者自行制定，而世界间的流转与交互则严格遵循平台核心协议。

## 典型场景：用户在两个世界之间移动

用户当前处于 World A，希望前往 World B：

1. **发起转场**：用户发起移动请求，系统通过 Transit 基础协议契约进行全程管控。
2. **中枢路由**：系统将转场路径规范路由至 OASIS：World A → OASIS → World B，杜绝不可控的世界间直连。
3. **身份保持**：转场过程中，用户的权威身份持续保持规范化，任何外部世界均无法隐式生成伪造身份。
4. **受控准入**：World B 依据自身业务规则接纳该参与者。用户依然保持一致的账号标识、社交关系与资产状态。

为什么必须经过 OASIS？因为点对点的跨世界互联会产生复杂度极高的 $N \times N$ 网状网关策略；而以 OASIS 为中枢的星型架构，将其简化为清晰可验证的 $N$ 条标准化协议契约（即每个世界与 OASIS 的交互契约）。

## 典型场景：世界离线时的安全回归

假设用户当前访问的创作者世界被其作者临时下线或发生异常：

- **无中枢架构**：用户会直接陷入连接中断或状态悬挂，平台缺乏安全承接的兜底空间。
- **OASIS 架构**：系统检测到目标世界不可达后，自动将用户平滑重定向回 OASIS。用户的身份凭据与会话安全完好无损，可随时安全选择并进入其他世界。

中枢不仅仅是出发点，更赋予了整个多世界系统抵御单点服务波动的弹性。

## 典型场景：创作者自主权与中枢边界

某创作者希望打造专属的“核心世界”，并期望自己旗下的所有衍生内容都在该世界内完成调度：

- **创作者世界的充分自由**：创作者完全可以打造规模庞大、体验丰富的优质世界，其世界在平台上是一等公民。
- **无法取代系统主世界**：平台的跨世界转场协议在架构上强制绑定 OASIS，创作者世界无法充当系统级转场仲裁者。
- **OASIS 不可跳过**：平台核心协议不开放未经中枢仲裁的世界直连通道。

不可替换性正是系统设计的核心所在：如果 OASIS 可以被任意品牌私有替换，那么平台赋予用户的跨世界连续性与安全保障也将随之瓦解。
