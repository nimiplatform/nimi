# 平台协议体系

平台协议为 Nimi 中的不同数字世界与交互表面提供统一的通用语言。它绝不限制世界创作者的内容发挥与叙事自由，而是为跨世界的数据交互建立清晰的标准契约，确保角色身份、智能体状态、社交图谱与空间漫游在不同界面和客户端上始终具备确定的语义。

本篇为面向开发者的架构概览。权威的平台底层规则归口于平台内核规范的 `P-PROTO-*` 规则族。

## 六大核心协议原语（Six Primitives）

每一个协议原语都是一块职责明确的固定契约接口。各个数字世界在其内部可以完全自主实现其特定业务规则；但任何需要跨越世界边界进行传递的数据或事件，均遵循这六大原语：

| 协议原语 | 涵盖语义与功能范围 |
| --- | --- |
| **Timeflow（时序流转）** | 跨世界的事件进程、时序协调与时间演化语义 |
| **Social（社交网络）** | 跨场景的人际社交图谱、好友关系与互动语义 |
| **Economy（价值经济）** | 虚拟资产、流通交换与经济状态记录 |
| **Transit（状态迁移）** | 角色或用户在不同世界、场景与上下文之间的漫游迁移 |
| **Context（情境共享）** | 跨端共享的环境设定、场域规则与情境上下文 |
| **Presence（在场状态）** | 用户或智能体在特定场景中的在场判定、可见性与准入条件 |

这些协议原语在设计上保持高度的抽象与普适性。例如，Timeflow 并不硬性规定“一小时等于六十分钟”，而是规定：当一个世界的内部时间流速需要被另一个世界或交互客户端所理解时，其推进状态应当如何被标准化表达与对齐。

## 为何协议优先于具体功能

如果没有底层的统一协议，每个业务功能就会陷入局部封闭与割裂：世界内部使用一套定义，桌面客户端又产生另一种理解，智能体则依据第三种逻辑行动。平台协议将共享语义锚定在不可被单个上层功能随意篡改的标准层，从根本上防止了系统状态的分裂与漂移。

这一原则带来明确的工程约束：任何涉及跨世界语义的新功能，都必须通过标准协议原语进行交互，严禁在协议外自建旁路。如果一个应用在应用层私自构建一套无法互通的孤立社交图谱，这并非系统扩展，而是制造了破坏一致性的未受控平行状态。

## 场景示例：跨世界识别同一段好友关系

假设 Alice 与 Bob 在“世界 A”中结为好友，随后 Bob 造访了“世界 B”。Social 原语定义了这段好友关系跨世界传递的标准方式：

1. 该好友关系拥有标准化的结构表达，使世界 A 和世界 B 均能准确解析。
2. 世界 B 可以应用其本世界的特定社交规则。例如在世界 B 中，“好友”身份仅开通文字私聊权限；而在世界 A 中，好友可能还共享特定的经济收益。
3. Bob 造访世界 B 绝不会反向篡改世界 A 中所记录的好友权威状态；若产生新的关系变更，必须经由各自世界的权威通道分别确认并记录。

Social 原语并不强求所有世界采用完全一致的好友逻辑，而是要求好友关系的跨世界表达符合公开、无歧义的契约标准。

## 协议与 Realm 的关系边界

平台协议是跨世界语义传递的接口契约；而 Realm 是世界权威状态与数据持久化的可信源。两者紧密协作但职责明确：

- **协议（Protocol）** 是定义交互语法的通用语言；
- **Realm** 是使用该语言表达并持久化保存的真实业务状态。

当一个世界推进了自身状态时，该变更持久化锚定在 Realm 中；当该变更需要被桌面端或其他世界读取感知时，则通过这六大协议原语进行结构化投递。

## 场景示例：贯穿多个协议原语的典型业务流

以一个数字世界中举办的“集市游园会”为例：

- **Timeflow** 驱动活动状态从“预约排期”推进至“活动进行中”，再到“活动圆满落幕”；
- **Presence** 精确判定当前在集市活动空间内活跃的智能体与玩家；
- **Social** 记录两位参与者在游园互动中建立的新联系；
- **Economy** 结算参与者购买虚拟道具的交易凭据；
- **Transit** 负责活动结束后引导参与者有序迁移返回各自的主城世界；
- **Context** 向各客户端与智能体实时广播当前集市的现场规则与氛围，使参与的智能体无需逐项翻查底层数据，即可自然理解当前场景并做出合乎情境的互动。

六大原语看似抽象，但在一个真实的业务场景中，它们往往有机协同，共同支撑起一致的跨世界体验。
