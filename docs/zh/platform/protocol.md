# 平台协议体系

平台协议为 Nimi 中的不同数字世界与客户端消费表面提供统一的交互语法。它不限制世界创作者的内部玩法与叙事自由，而是通过标准化契约结构，确保账号身份、社交关系、情境上下文与跨世界流转在各个界面间保持一致的语义。

本文为面向开发者的架构概览，底层协议规则归口于平台内核规范的 `P-PROTO-*` 规则族。

## 六大核心协议原语（Six Primitives）

每个协议原语对应一块边界清晰的契约表面。各个数字世界可自主设计内部业务规则，而跨世界传递的状态与事件语义则遵循以下六大原语：

| 协议原语 | 涵盖语义与契约范围 |
| --- | --- |
| **Timeflow（时序流转）** | 跨世界的事件生命周期、时序推进与时间尺度表达 |
| **Social（社交网络）** | 跨场景共享的社交图谱、好友关系识别与互动契约 |
| **Economy（价值经济）** | 经济规则配置、收益分成预览与价值交换契约 |
| **Transit（状态迁移）** | 世界或空间上下文之间转场与回归的路由契约语义 |
| **Context（情境共享）** | 跨端共享的环境设定、场域规则与情境上下文 |
| **Presence（在场状态）** | 用户或智能体在特定场景中的在场判定、可见性与准入条件 |

这些协议原语在设计上保持必要的抽象。例如，`Timeflow` 并不强制规定所有世界采用相同的时间流速，而是定义当一个世界的时序状态需要被其他客户端或世界读取时，应当如何标准化表达。

## 为何协议优先于具体功能

如果缺乏统一协议，各端功能很容易演变为彼此割裂的局部实现：世界内部按一套逻辑定义状态，桌面端按另一套逻辑解析，智能体又基于第三种假设运行。平台协议将共享语义固定在统一的契约层，避免单一功能表面私自制造平行状态。

这也意味着：任何涉及跨世界语义的能力都应接入标准协议原语，而非在应用层自建孤立图谱；同时，共享协议接口仅提供标准化的表达与访问通道，绝不会授权任何应用或世界越过资源所有者（Owner）私自变更权限与状态。

## 场景说明：跨世界识别同一段好友关系

假设 Alice 与 Bob 在“世界 A”中结为好友，随后 Bob 访问“世界 B”。在 `Social` 原语与 Realm 权威模型下：

1. **Realm 维护唯一共享真相**：Alice 与 Bob 的好友关系作为全局社交事实保存在 Realm 中，而不是由世界 A 和世界 B 各自维护一份互不相干的好友账本。
2. **世界自主定义场景准入与玩法条件**：世界 A 与世界 B 均可基于这段共享好友关系配置各自的局部规则。例如在世界 B 中，好友关系可用于解锁场景准入或私聊互动；在世界 A 中，好友可能满足组队玩法的参与条件。
3. **严格的变更边界**：Bob 访问世界 B 或触发世界内部规则，绝不会私自改写全局好友状态；任何对好友关系本身的修改，都必须经由所有者（Owner）授权并通过 Realm 的权威通道完成。

`Social` 原语既保证了全局社交关系的一致性，又为不同世界保留了差异化的玩法空间。

## 协议与 Realm 的关系边界

平台协议与 Realm 在架构中各司其职：

- **协议（Protocol）**：定义跨端、跨世界的交互语法与契约结构（涵盖六大原语以及 `WorldState`、`WorldHistory` 等规范定义）。
- **Realm**：持久化保存全局权威实体与状态真相，包括账号身份、社交图谱、`WorldCore` 与角色设定等。

需要注意当前的实现边界：Realm 当前已承载全局身份、社交关系、`WorldCore` 与角色设定等核心状态；而 `WorldState` 与 `WorldHistory` 仍属于规划中的协议契约，并非当前 Home 中已可执行完整世界状态流转的实时账本。同样，`Economy` 相关的收益分成预览并不等于真实资金结算，创作者提现尚未接通。

## 协议契约场景：多原语协同的游园会流程

以下通过一个“集市游园会”的协议设计场景，展示六大原语如何在架构契约层面协同工作：

- **Timeflow** 表达活动从“排期预告”到“进行中”再到“已结束”的阶段演进；
- **Presence** 描述当前集市空间内满足准入条件并处于可见状态的玩家与智能体；
- **Social** 读取 Realm 中的现有好友关系，并规范新社交请求的发起格式；
- **Economy** 约束活动内的交易规则与收益分成预览结构；
- **Transit** 定义参与者进入活动世界及结束后返回主世界目标的路由契约；
- **Context** 向客户端与智能体广播集市的现场规则与情境设定，使智能体能够做出符合当前场景的互动响应。
