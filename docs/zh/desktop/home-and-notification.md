# 主页与通知

主页是你的社交动态加常用入口；通知收着未读数和近期事件。两个面合起来，回答一个问题：「最近有什么新情况？」

## 主页

| 能力 | 行为 |
| --- | --- |
| 社交动态 | 来自社交关系的帖子与状态 |
| 快捷入口 | 常用的世界、Agent、会话 |
| 推荐内容 | 经过策划的内容呈现 |
| 跨域卡片 | 来自聊天、用户画像等其他能力域的卡片 |

主页是个展示面，不是数据来源。它把你 Nimi 账户里的社交动态、世界与 Agent 的更新取出来，整齐地摆给你看。

## 跨域入口

主页上的卡片可以指向别的功能：「打开与 X 的会话」「看 Z 的资料」。有个设计决定值得知道：**主页本身不执行这些操作**。

你点击之后，主页把事情交给拥有该动作的模块——聊天、经济或资料——由对方走完整个流程。

所以从主页点进去的快捷操作，和你直接去对应模块里做，行为完全一样。

## 通知

| 能力 | 行为 |
| --- | --- |
| 通知列表 | 近期通知 |
| 未读角标 | 在导航上可见 |
| 标记已读 | 单条或全部 |
| 取数方式 | 未读计数走轮询 |

未读数靠轮询刷新。这是个不起眼的细节，但它设定了预期：未读数按轮询节奏更新，不走实时推送。

## 读者场景：在主页处理一张卡片

主页上出现一张卡片，邀请你打开一段直接聊天。

1. **卡片浮现**。主页读取相应的社交事件并渲染卡片。
2. **你点「打开聊天」**。主页不创建或变更线程，而是通过准入回调交给聊天能力。
3. **聊天能力接手**。两位人类用户之间的直接聊天按 Realm Chat 契约打开。
4. **审计记录**。点击与跳转都计入审计链路。

主页是发现面，聊天是动作面。两者协作，但谁也不持有对方的真相。

## 读者场景：查看通知

你打开通知。

1. **列表加载**。最近的通知逐条呈现。
2. **未读计数**。角标显示 N 条未读。
3. **标记已读**。逐条阅读，标记已读，角标递减。
4. **轮询**。未读计数按准入的轮询策略刷新。

通知本身是有边界的。新的通知种类必须有对应准入的通知契约。
