# 委托控制与安全审计

> **规范状态**：设计规范 / 预留契约。在外部动作注册表为空（`EXTERNAL_AGENT_ACTION_REGISTRY_EMPTY`）期间，外部智能体动作执行保持禁用。当前桌面端版本中，用户可在“高级与诊断 → 权限与访问”中查看网关与令牌状态；下文描述的交互式审批卡片与隔离区审查属于后续生效的目标安全契约设计。

委托控制（Delegation Control）定义了 Nimi 桌面端的安全控制面板设计。当外部 AI 智能体动作执行能力正式就绪后，该控制台负责在桌面端明确弹出用户审批，确保所有敏感操作必须获得用户的知情与许可。

底层安全防火墙与裁决引擎的技术设计，详见 [Runtime → 委派能力](/zh/runtime/delegated-capability)；本文档聚焦于桌面端的交互控制与决策审计契约设计。

## 核心安全控制机制（契约设计）

1. **显式用户审批（契约设计）**：在委托契约设计中，外部 AI 提出的任何涉及系统级改动或跨域访问的动作，均需在桌面端由用户点击“批准”方可继续执行；未经用户授权的操作将被系统默认 fail-closed 拦截。
2. **安全隔离区审查（契约设计）**：当模型输出触发了安全策略或敏感数据过滤器时，内容将被暂扣在隔离区。用户可在控制台清晰审阅隔离原因与证据，自主决定放行或安全丢弃。
3. **可解释的决策依据**：每次审批弹窗均清晰展示调用方身份、提议执行的具体参数、触发审批的安全规则以及潜在风险提示。

## 权责边界划分

| 桌面端控制面 | 底层 Runtime 安全引擎 |
| --- | --- |
| 渲染审批卡片与交互式放行/拒绝选项 | 执行输出防火墙规则与敏感度分类 |
| 直观呈现隔离证据与详细上下文 | 强制阻断未通过授权的底层调用 |
| 收集并持久化用户的个性化策略偏好 | 记录脱敏且有界的本地审计事件 |

## 规范工作流（契约设计）

以下场景展示了当外部动作注册表与网关执行正式开放后，委托契约所定义的安全控制流程：

### 1. 外部工具调用审批
1. **触发审批**：外部 AI Agent 计划执行一项本地文件写入操作，底层防火墙判定该动作属于敏感操作（`APPROVAL_REQUIRED`）。
2. **弹窗确认**：桌面端右下角弹出审批卡片，详细展示操作目标、文件路径及修改摘要。
3. **用户裁决**：
   - 若用户点击“批准”，Runtime 在审计日志中记录该授权后执行该动作；
   - 若用户点击“拒绝”，该动作立即终止并安全返回失败状态。

### 2. 隔离与阻断审查
当智能体提议的操作或输出被安全策略判定为 `QUARANTINED` 时，该内容将被即时拦截，绝不会在未经确认前流入下游消费界面。在委托控制流程中，系统会向用户呈现具体的拦截原因与判定依据，由用户做出明确裁决。
