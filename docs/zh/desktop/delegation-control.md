# 委托控制与安全审计

> **规范状态**：设计规范 / 预留契约。在外部动作注册表为空（`EXTERNAL_AGENT_ACTION_REGISTRY_EMPTY`）期间，外部智能体动作执行保持禁用。当前桌面端版本中，用户可在「高级与诊断 → 权限与访问」中查看网关与令牌状态；下文描述的交互式审批卡片与隔离区审查属于后续生效的目标安全契约设计。

委托控制（Delegation Control）定义了 Nimi 桌面端的安全控制面板设计。当外部 AI 智能体动作执行能力启用后，该控制面会在敏感操作执行前弹出审批提示，确保所有跨边界或敏感操作均经过用户的知情同意。

底层安全防火墙与裁决引擎的架构设计，详见 [Runtime → 委派能力](/zh/runtime/delegated-capability)。本文档聚焦于桌面端的交互界面与决策审计契约。

## 核心安全控制机制（契约设计）

1. **显式用户审批**：外部 AI 提出的任何系统级改动或跨边界动作，均需用户在桌面端手动确认后方可执行；未获授权的操作默认按 fail-closed 原则拦截。
2. **安全隔离区审查**：当生成内容触发安全策略或敏感数据过滤器时，系统会将其拦截至安全隔离区。用户可在控制台查看具体的触发依据与上下文，自主决定放行或丢弃。
3. **透明的决策依据**：每次审批弹窗都会清晰列出调用方身份、请求执行的操作及参数、触发检查的安全规则以及潜在风险。

## 权责边界划分

| 桌面端控制面 | 底层 Runtime 安全引擎 |
| --- | --- |
| 渲染审批卡片并接收用户的放行或拒绝决定 | 执行防火墙规则评估与内容敏感度分类 |
| 直观展示隔离证据与可审查的上下文 | 强制执行安全边界，拦截未授权的底层调用 |
| 保存用户的非关键通知默认偏好 | 为每次安全裁决记录脱敏且有界的本地审计事件 |

## 规范工作流（契约设计）

以下场景展示了当外部动作注册表与网关执行启用后，委托契约如何管控外部智能体操作：

### 1. 外部工具调用审批
1. **触发审批**：外部 AI Agent 请求写入本地配置文件，安全防火墙将该操作标记为需审批（`APPROVAL_REQUIRED`）。
2. **弹窗确认**：桌面端弹出审批卡片，展示目标路径、修改内容差异及调用原因。
3. **用户裁决**：
   - 若点击「批准」，Runtime 将授权决定写入审计日志并继续执行；
   - 若点击「拒绝」，操作立即中止并返回拒绝访问状态。

### 2. 隔离与阻断审查
当智能体提议的操作或输出被安全策略判定为 `QUARANTINED` 时，内容会被立即拦截，不会流入下游应用界面。系统会将具体的拦截决定与判定依据呈现给用户审阅，而不会静默绕过安全护栏。
