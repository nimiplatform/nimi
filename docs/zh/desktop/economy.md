# 经济

桌面端的经济页就是钱包（Wallet）。余额、交易历史、充值、订阅状态和提现都在这里看。数字来自你的 Nimi 账户（Realm `R-ECON-*`），桌面端负责展示。

## Wallet 暴露什么

| 子面 | 行为 |
| --- | --- |
| 余额 | 来自 Realm 的平台规范化余额 |
| 交易历史 | 仅追加的经济事件流 |
| 充值 | 在准入流程下加资金 |
| 订阅状态 | 当前订阅（如有） |
| 提现 | 在准入流程下提资金 |

所有经济操作都需要有效的 bearer token。收入与结算的规则由 Realm `R-ECON-003` 定义。

## 仅追加的经济流

Realm 的经济账是**只增不改**的。每一笔货币交易、收入归因和结算，都是一条语义明确的类型化事件。没有任何内容会悄悄改写。

| 维度 | 取值 |
| --- | --- |
| 存储 | 仅追加流 |
| 事件类型 | 显式，在 kernel 层准入 |
| 结算 | 强类型事件，不是自由格式账目 |
| 审计 | 任何变更都可重建 |

所以桌面端里的「交易历史」是真实记录，不是事后拼出来的视图。

## AI 计算成本不是 Realm 真相

一个值得知道的设计决定：AI 计算成本**不在**平台经济里。平台经济管的是平台层面的价值：订阅、收入结算、创作者经济事件和货币交易。AI 计算成本由 Runtime 单独核算。两本账永远不会合并。

## 读者场景：创作者收到收入结算

世界创作者的世界从已准入的来源获得收入。

1. **事件累积**。每条收入事件都带有强类型来源归因。
2. **分润计划**。创作者的分润计划在 `R-ECON-*` 下准入。
3. **结算事件**。结算时，结算事件被追加；创作者的 Wallet 余额更新。
4. **提现**。创作者按准入的提现流程提取。
5. **审计**。从收入归因到结算和提现，整条链都可以重建。

如果创作者要追问"这笔收入从哪儿来"，强类型事件流能给出回答。

## Wallet 不展示什么

| 关注点 | 原因 |
| --- | --- |
| 其他用户的余额 | 每个用户私有 |
| AI 计算成本细节 | 归 Runtime，是另一回事 |
| 世界内部货币 | 创作者可以在自己的世界里跑内部货币，但那不是平台规范态 |
