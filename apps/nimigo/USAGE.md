# NimiGo 使用指南

把资料、想法与项目，推进到可以继续使用的成果。

## 开始第一项工作

1. 在左下角选择一位已有的 Nimi Agent 作为工作搭档。
2. 建立项目和工作，写清受众、目标、需要包含的内容与约束。
3. 添加文本或 Markdown 资料，选择适用的工作方法，再点击“交给搭档开始”。
4. 查看推进步骤，回答搭档提出的必要问题，等待成果保存。

“已交付”表示实际保存了成果或完成了经你审核的源业务修改。若搭档只是回复而没有保存，工作会显示“待交付”；失败或停止时，已有成果仍然保留。

补充回答和继续委托会参考这项工作已保存的近期交流，包括此前明确的受众、语气等要求。只带入当前工作的有限前文；过长内容会省略并向搭档标明。当前目标、资料和本次要求优先于历史交流，不会重新执行旧委托。

选中项目后可以“编辑项目”，调整名称和共同背景。搭档执行每项工作时会参考这些背景。工作详情中可修改名称、目标、归属项目和方法；打开资料后可以修订内容。修改目标、方法或资料会让工作回到“待开始”，保留已有成果与执行记录。来自生态来源的资料修订会保留出处、标明“用户修订”，只修改工作中的副本。

## 查看、修订和带走成果

在工作侧栏、“最近成果”或“成果库”打开文档。点击“编辑”后保存新版本，原版本保留。再点“交给搭档改进”，继续委托中会带出最新保存的版本；确认或补充要求后发送。点击“在文件夹中显示”可定位到实际 Markdown 文件，方便复制与使用。

选定已保存版本后，点击“复制版本引用”，即可将其粘贴到 NimiDay 等生态应用的资料入口中。复制的是你选中的已保存版本；之后保存新版本，不会自动更新这条引用，其他应用读取的是该特定版本的确定性内容。

## 回来继续工作

工作台顶部优先展示“需要你处理”和“最近成果”，便于快速接续上下文：

- **排队中的工作**：重新打开应用后保持在“待开始”状态，保留已添加的资料和要求，由你确认后手动开始。
- **状态待确认**：若遇到网络波动或程序重启导致状态未决，工作卡片会提示“待确认”。需先核对执行结果与已有成果，再决定继续推进或重新发起，不会盲目自动续跑。
- **重试委托**：若任务失败，点击“重试这次委托”会沿用本次补充的要求继续尝试，无需从头输入。

## 把好做法用到下一项工作

完成一项工作后，可以“提炼为方法”，调整做法与交付标准，再用于新工作。方法属于工作空间，更换搭档后仍可使用。不同安装来源的工作空间分别保存，不会自动合并。

## 连接、后台与成果读取

在工作详情中可使用已授权的外部连接读取素材。直接点击“读取集成资料”即可将内容保存为工作素材，再交由搭档进行梳理与分析。敏感凭据始终由 Nimi 统一安全保管，不会暴露给第三方应用。

已开始的分析在关闭窗口后由后台继续推进，完成真实成果版本保存并按偏好发送通知。可在菜单中选择“退出并停止 NimiGo”结束整个应用运行。

工作交流通过独立 Agent 业务入口执行并保存在 NimiGo 中，与日常闲聊记忆保持独立，互不混淆。如需语音通话，可点击语音入口进入规范通话。

## 例行与消息

每日例行需要 NimiGo 窗口与 Nimi 保持运行；多个例行任务按加入顺序排队执行。你可以暂停例行，或手动开始。交付结果可在 Nimi Home 中查看，点击即可返回对应工作。

## 生态来源与桌面搭档

“生态来源”可为项目选择关注的应用来源，搭档查询时也沿用该范围。选择一项已有工作后可直接加入资料，也可以带入新工作，出处与更新时间均完整保留。

Avatar 会交接给当前同一位搭档。语音对话需要对应 Agent 配置了可用声音和实时对话设置；工作回复保存在 NimiGo 中。

## 遇到中断与异常处理

- **停止任务**：随时可以点击停止当前正在进行的工作，停止前已保存的成果版本完整保留，不会影响搭档在其他工作中的进度。
- **核对实际成果与未决状态**：只有实际保存到文档库中的内容才是最终交付成果。如果搭档仅在对话中作出口头建议，可在确认后让其生成正式版本；若执行中断且状态未确认，需先核实上一步骤的执行结果，再决定是否继续或重试。
- **服务重连**：若提示 Runtime 暂不可用，可在 Nimi 恢复后点击重试入口，继续当前工作。
