# Platform gaps during App work

For a request limited to feasibility, capability fit or cost, use [Audit](audit.md) and report the gap and proposal. The implementation loop below requires implementation authorization. When continuing from an assessment, use [Audit handoff](audit.md#handoff-to-implementation).

Start with the original user task, the condition that requires the behavior, and the selected public SDK/Kit inputs and outputs. Distinguish configuration, documentation, an existing-contract defect, a missing carrier or implementation behavior, and a required new capability. State which selected workflow the gap blocks; an optional backend or old configuration control is not automatically a platform requirement, while an explicitly required feature cannot be dropped. Keep model-content quality separate from a broken contract or App regression. A generated sample succeeding does not establish that the App's required result is available.

When the user has authorized adapting the App and extending or fixing Nimi as needed, continue the platform work under that authorization. Enter the Nimi repository through its AGENTS.md and `nimi-app-runtime-evolution` skill, or give the platform owner the bounded gap when source work is outside this task's resources. App Tools does not create or own a cross-repository task workflow. If new platform capabilities are excluded, report the unmet requirement without silently removing the workflow or introducing App-owned inference.

Supply the affected public call and package combination, the actual required input/output or a minimal representative input, expected and observed behavior, and available typed failure/trace. Preserve the original input for the return check. Reuse existing project notes; avoid secrets and unnecessary user data in shared diagnostics. Missing Desktop is a launch prerequisite, not a reason to withhold a code-confirmed missing operation. A same-package reference can isolate foundation differences but cannot rule out a platform defect.

The platform owner decides whether the gap belongs to Runtime execution, SDK/Kit/native projection, a framework adapter, or App Tools. App workflows, tool callbacks, subtitle/media composition and project recovery remain App-owned. Do not copy Runtime internals or install a private forwarding API while waiting for the shared fix.

Consume the returned complete package combination using [Platform upgrade](upgrade-platform.md). Package consumption does not require a Nimi source dependency or public publication; authorized platform development can still inspect and change its own source. Keep the existing tarball, lock and native-profile boundaries. Reuse unaffected tests and baseline results, then return to the original App task and verify the actual downstream result through [Acceptance](acceptance.md).

Close the bounded platform issue with the shared fix or clarified usage, its regression, the tested combination and the App return result. Distinguish evidence obtained now, reusable prior evidence, and remaining NOT-VERIFIED paths. Keep the current delivery summary separate from historical notes; completing one platform gap does not declare the ongoing App adaptation finished.
